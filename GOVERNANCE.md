# Governance

SiteOS currently uses a maintainer-led governance model.

## Maintainer responsibilities

Maintainers are responsible for:

- triaging issues;
- reviewing pull requests;
- protecting project and contributor data;
- maintaining releases and changelogs;
- preserving backward compatibility where practical;
- documenting schema and migration changes.

## Decision making

Small changes are decided through pull-request review. Larger changes should begin with a GitHub issue describing the construction workflow, alternatives, migration impact, and acceptance criteria.

## Data policy

Public repository content must use synthetic data. Real company, client, project, site, personnel, schedule export, drawing, photograph, or credential data must not be committed.

## Automated tools

Automated coding and review tools may assist maintainers. Human maintainers remain responsible for merge and release decisions.
